# Telegram Finance Bot — первая партия

Это начальный рабочий каркас Telegram-бота на Python для размещения на Render.

В этой версии есть:

- Telegram-бот на aiogram 3;
- HTTP-сервер FastAPI;
- приём обновлений Telegram через Webhook;
- проверка секретного токена Webhook;
- команды `/start` и `/help`;
- адреса проверки сервиса `/` и `/health`;
- централизованная загрузка настроек из переменных окружения.

Финансовый учёт, пересылка сообщений, SQLite, Inbox/Outbox, Google Sheets,
MEGA, резервное копирование и восстановление будут добавлены следующими партиями.

## 1. Структура файлов

Все запускаемые Python-файлы находятся вместе, в корне проекта. Папок с Python-модулями нет.

- `main.py` — точка запуска приложения.
- `config.py` — настройки и переменные окружения.
- `bot_factory.py` — создание Telegram-бота.
- `base_router.py` — базовые команды.
- `update_middleware.py` — журналирование обновлений.
- `dispatcher_factory.py` — создание диспетчера и подключение обработчиков.
- `permissions.py` — проверка прав администратора.
- `lifecycle.py` — запуск бота и регистрация Webhook.
- `webhook_app.py` — HTTP-приложение FastAPI.
- `requirements.txt` — зависимости Python.
- `.env.example` — пример переменных окружения.

## 2. Создание бота в Telegram

1. Открой Telegram и найди `@BotFather`.
2. Создай бота командой `/newbot`.
3. Скопируй выданный токен.
4. Не публикуй токен и не добавляй его в GitHub.

## 3. Загрузка в GitHub

Загрузи все файлы из архива непосредственно в корень репозитория.
Не создавай дополнительную папку вокруг файлов проекта.

Файл `.env.example` можно хранить в GitHub: в нём только примеры.
Настоящий `.env` и секреты в репозиторий загружать нельзя.

## 4. Развёртывание на Render

Создай на Render сервис типа **Web Service** и подключи GitHub-репозиторий.

Параметры:

- Runtime: `Python`
- Build Command: `pip install -r requirements.txt`
- Start Command: `python main.py`

В разделе Environment добавь:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather |
| `RENDER_EXTERNAL_URL` | Публичный HTTPS-адрес Render-сервиса |
| `WEBHOOK_SECRET` | Случайный секрет из латинских букв, цифр, `_` и `-` |
| `ADMIN_IDS` | Необязательно: Telegram ID администраторов через запятую |
| `LOG_LEVEL` | Необязательно: `INFO` |

Render обычно сам предоставляет `PORT` и `RENDER_EXTERNAL_URL` для Web Service.
Если `RENDER_EXTERNAL_URL` не появился автоматически, укажи публичный адрес сервиса вручную.

`WEBHOOK_SECRET` нужно придумать самостоятельно. Не используй токен бота в качестве webhook-секрета.

## 5. Локальный запуск

1. Установи Python 3.10 или новее.
2. Скопируй `.env.example` в файл `.env`.
3. Заполни обязательные переменные.
4. Установи зависимости:

   `pip install -r requirements.txt`

5. Запусти:

   `python main.py`

Для локального тестирования Telegram Webhook нужен публичный HTTPS-адрес.
Обычный `localhost` Telegram использовать для доставки обновлений не сможет.

## 6. Проверка работы

После запуска открой в браузере:

- `https://адрес-сервиса/` — общий статус;
- `https://адрес-сервиса/health` — проверка доступности.

Затем отправь своему боту `/start`.

## 7. Важные ограничения этой версии

- Это только первая партия проекта, а не готовый финансовый бот.
- Пока нет постоянного хранения сообщений и финансовых операций.
- Пока нет Inbox/Outbox и гарантированного восстановления после сбоя.
- Локальные файлы бесплатного Render нельзя считать постоянным хранилищем.
- Webhook не удаляется при остановке приложения, чтобы не сбрасывать регистрацию при перезапуске.
- `drop_pending_updates=False`: ожидающие обновления не удаляются намеренно.
- Keep Alive не гарантирует непрерывную работу бесплатного Render.

Не используй эту версию для реального финансового учёта до подключения базы данных,
журнала событий, очередей, резервного копирования и тестов восстановления.
